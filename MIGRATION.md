# Migration & setup — Bulls ⚔ Unicorns

Moving to new hardware, or setting up from the archive. Read `AGENTS.md` for what the project *is*;
this document is purely how to get it running and what must not be lost.

## 0. ⛔ READ FIRST — the mainnet vault key is not backed up anywhere

**The private key controlling the live vault `6wLK7paKz2es3nG9jdVvrnHMNUCPkognh8yQUFJ7Zete` exists
in exactly one place: the Fly secret `VAULT_SECRET_KEY`.**

I checked every keypair in this repo and on the machine. The local `engine/.vault-keypair.json` is
the **devnet** vault (`4iDuXiq95uRT74xvGkz4icqnu6ma9qKZmzDuquRZGAFy`), not this one.

Fly secrets are **write-only** — they cannot be read back through the CLI or dashboard. So if the Fly
app is deleted, the org is lost, or the account is locked out, **the vault key is gone and every
token in it is permanently unrecoverable.** That includes the house float and every player balance.

This is not a laptop-migration risk. It is true right now.

### Back it up before anything else

The running machine has the key in its environment. Retrieve it yourself — it should not pass
through a chat transcript or an agent's context:

```bash
fly ssh console --app bulls-arena-engine -C "printenv VAULT_SECRET_KEY"
```

Save the output somewhere durable and offline (password manager, encrypted volume, hardware-backed
store). Then verify it is the right key before trusting the backup:

```bash
cd engine
node -e "const {Keypair}=require('@solana/web3.js');const fs=require('fs');
const a=JSON.parse(fs.readFileSync(process.argv[1],'utf8'));
console.log(Keypair.fromSecretKey(Uint8Array.from(Array.isArray(a)?a:a.secretKey)).publicKey.toBase58());" \
  /path/to/your/backup.json
# must print: 6wLK7paKz2es3nG9jdVvrnHMNUCPkognh8yQUFJ7Zete
```

**If the app is currently stopped, start it first** — a stopped machine cannot be SSH'd into, and if
it can never be started again the key is already unreachable.

Do the same for `SESSION_SECRET` (invalidates every session if lost — recoverable, but everyone gets
logged out) and for the Helius RPC URL in `SOLANA_RPC` (re-obtainable from the Helius dashboard).

## 4. The environment contract

The engine reads ~100 env vars; only a handful are required. Everything else has a working default.
`engine/.env.example` documents them all.

### Required
| Var | Where it comes from |
|---|---|
| `SOLANA_RPC` | Helius mainnet URL **with API key**. Not recoverable from Fly — get from the Helius dashboard. |
| `VAULT_SECRET_KEY` | The vault keypair as a JSON byte array. **See §0.** |
| `SESSION_SECRET` | Any long random string. Changing it logs everyone out. |
| `BOT_POOL` | Comma-separated pool pubkeys — regenerate from `engine/data/bot-pool.json`. |
| `CHAIN_CONFIG` | Contents of `engine/mainnet.json`. |

### Live tuning values (as currently set)
```
PAUSED=1                 # currently paused — unset to resume
ENABLED_ARENAS=us-extraction
LOBBY_MS=9000
PLAY_MIN=5  PLAY_MAX=9   # entrants per side; scales with human stake
BOT_STAKE_USD_MIN=0.60
BOT_COMMIT_MIN=0.12  BOT_COMMIT_MAX=0.32
BOT_BANK_USD_MIN / BOT_BANK_USD_MAX / BOT_MIN_RUNWAY / SWARM_SIZE / MIN_PER_SIDE
MEMO_ON_CHAIN=1  MEMO_BATCH=1
SWAP_JITO_URL / SWAP_JITO_TIP
WHITELIST                # allowlisted wallets
```

Setting a secret restarts the machine — which is a clean pause (open stakes are refunded and the
ledger is persisted on SIGTERM). Batch changes:
```bash
fly secrets set A=1 B=2 --app bulls-arena-engine          # one restart
fly secrets set A=1 --stage --app bulls-arena-engine      # stage, applied on next deploy
```

## 5. Deploying

```bash
git branch --show-current      # ⚠ see AGENTS.md §9 before deploying
fly deploy . --config engine/fly.toml --dockerfile engine/Dockerfile --ha=false --app bulls-arena-engine
```

**Known deploy behaviours**
- A `401 Unauthorized` on the *post-deploy status update* does not mean the release failed. It has
  happened three times; the release landed each time. Verify with `/health` and the served markup
  rather than trusting the exit code.
- A health-check timeout **does** mean it failed. Roll back:
  ```bash
  fly releases --image --app bulls-arena-engine       # find the last "complete"
  fly deploy --app bulls-arena-engine --image <that image> --ha=false
  ```
- **Wait ~2 minutes after any deploy before measuring anything.** See `AGENTS.md` §7.

### Pause / resume
```bash
fly secrets set PAUSED=1 --app bulls-arena-engine       # rounds halt; withdrawals stay live
fly secrets unset PAUSED --app bulls-arena-engine       # resume
```

## 7. Verifying the migration worked

Work through these in order; each is cheap and catches a different failure:

1. `npm test` (production subset) → ~343 passing
2. `fly status` → machine `started`
3. `curl /health` → `{"ok":true,...}`
4. `curl /solvency` → `ok: true` for every asset, `frozen: false`
5. `curl /float` → ledger and chain within ~$2 of each other
6. `node engine/mainnet-canary.mjs` → dry run, all gates pass, spends nothing
7. Load the site → arena renders; if `PAUSED=1`, the paused screen shows
8. Click **Verify last round** → both commitment links tick (see `AGENTS.md` §4)

If 8 fails while 1–7 pass, the client's `deriveSeedJS` has drifted from the engine. That is the one
failure that looks like fraud rather than a bug — fix it before resuming.

## 8. If something is wrong

| Symptom | Cause seen before |
|---|---|
| Boots then exits code 1, restart-loops | Fork kill switch on a mainnet RPC — `AGENTS.md` §9 |
| Anchoring silently off (`posted: 0`) | Same fork coupling in `memo.ts`, or `MEMO_ON_CHAIN` unset |
| Withdrawals frozen | Solvency breach — **investigate, do not override.** `/solvency` names the asset |
| Every round shows "MISMATCH" | Client/engine seed derivation drift — §7 step 8 |
| Ledger claims less than chain | Normal drift, auto-corrected within ~5 min. Only worry if it grows past ~$5 and stays |
| Ledger claims *more* than chain | Over-claim. `WRITEDOWN_OVERCLAIM=1` for one boot, then unset |

Logs: `fly logs --app bulls-arena-engine --no-tail`
